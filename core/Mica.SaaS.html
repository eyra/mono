    Mica.SaaS behaviour (mica v0.1.0)

    Copy Markdown View Source

    A SaaS built on Mica, and the composition of the configured one.

    Each SaaS has one module that implements this behaviour (Next.SaaS, MicaSaas.SaaS). It lists the systems the SaaS is made of and carries the SaaS-level config. The build picks one in its config:

    config :mica, saas: Next.SaaS

    Mica reads the value at runtime only. At boot validate!/0 builds the composition, the contributions of all systems, checks it and caches it; the readers below (signal_handlers/0, grants/0, ...) take their part from that cache. Each SaaS has its own router, which splices the routes of its systems (Mica.SaaS.Routes), so no Mica module is compiled against the configured SaaS. Set :saas only in the SaaS's config, not in runtime.exs: the endpoint config of a build is the SaaS's.

    Summary

    Callbacks

    endpoint()

    The SaaS's endpoint, built with use MicaWeb.Endpoint.

    feature_flags()

    The SaaS defaults of declared feature flags: [password_sign_in: true]. Every name must be declared by one of its systems (Mica.System.feature_flags/0).

    identify_page(arg1)

    The page where a user enters an email address and is sent on to the way they sign in (a one-time code or an identity provider), for a creator or a participant. Mica appends a return path.

    member_sign_in_page(return_to)

    Where a signed-out user is sent to sign in for a page participants open, which they return to.

    menu_builder(arg1)

    The menu builder for a layout.

    menu_items()

    The MicaWeb.Menu.ItemsProvider implementation.

    router()

    The SaaS's router, use Phoenix.Router with Mica's pipelines and routes (MicaWeb.Pipelines, Mica.SaaS.Routes, MicaWeb.BaseRoutes). The endpoint plugs it.

    session_path()

    The path of the SaaS's session controller: the password sign-in form posts to it, and signing out deletes it.

    sign_in_options_page()

    The page that offers every way the SaaS has to sign in (a password, identity providers). Mica sends users there after they sign out, reset their password or fail to sign in through a provider.

    sign_in_page()

    Where a signed-out user is sent to sign in. Mica has no sign-in pages of its own: this callback and the four below name the SaaS's, and none has a default.

    sign_up_page(user_type, post_signup_action)

    Where a signed-out user is sent to sign up instead of the password sign-up page (/user/signup/:user_type), or nil to keep that page. The page's post_signup_action param is passed along, nil when it has none.

    signed_in_page(arg1)

    Where a user lands after signing in, unless a return path is set.

    start_pages()

    The MicaWeb.StartPageProvider implementation.

    systems()

    The systems the SaaS is made of: Mica.Systems.all() ++ its own systems.

    title()

    The product name shown in page titles.

    put_composition(parts)

    Test hook: replaces parts of the composition for every process. Returns the composition it replaced, to put back when the test ends:

    previous = Mica.SaaS.put_composition(signal_handlers: [MyTest.Switch])
on_exit(fn -> Mica.SaaS.put_composition(previous) end)

    The result is not checked, so a test can put a broken composition. A test that calls it must not be async.

    With no SaaS configured and no composition yet, systems: builds a composition of those systems that is not a SaaS's: Mica's own tests run on put_composition(systems: Mica.Systems.all()). It has no SaaS module, router or endpoint: module/0, endpoint/0 and router/0 raise in it, and so does every Mica.SaaS callback.

    The Ecto schemas of every application in the composition: Mica's and those of the applications that hold the SaaS module or one of its systems. Mica.Repo.orphan?/2 and Mica.Authorization scan them.

    validate!(saas)

    The composition of saas, after checking it. Raises on:

    • a SaaS module that is no Mica.SaaS, or a system that is no Mica.System
    • an endpoint that is no MicaWeb.Endpoint, or a router that is no Phoenix.Router
    • a system, signal handler, notifier, sign-in handoff or assignment template listed twice, or an event type that two notifiers declare
    • a notify channel, Oban queue, Oban cron, Desktop section id or BFF page that two systems declare
    • a flag default that no system declares
    • a permission granted twice, unless the later grant says widen: true; each widening is logged
    • a notifier event routed to a channel that no system declares
    • a tool or project item type that is no Mica.Tool or Mica.ProjectItem, whose name two of them declare or is reserved ("none"), or whose schema two of them share; a tool whose Frameworks.Concept.ToolModel.key/1 is not its type
    • a director name that two systems declare
