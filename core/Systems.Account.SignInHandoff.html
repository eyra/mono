    Systems.Account.SignInHandoff behaviour (core v0.1.0)

    View Source

    Takes over the end of an identity-provider sign-in, for example to hand it to a native app instead of continuing on the site. Systems list their handoffs in Core.System.sign_in_handoffs/0.

    The identity-provider flows (their callbacks and the move-your-account confirm and decline) end through sign_in/5 and end_sign_in/4, which ask the handoffs in Core.SaaS.sign_in_handoffs/0 order before they do what the site does. Other sign-ins don't ask them.

    hand_off(t, provider, t, first_time?)

    Returns {:ok, conn} with the response to send when the handoff takes this sign-in through provider, or :skip. first_time? is true for a user who registered with this sign-in.

    hand_off_unfinished(t, provider, arg3)

    Returns {:ok, conn} with the response to send when the handoff takes a sign-in through provider that ended without signing in: :failed (the provider or the registration failed) or :cancelled (the user stopped it).
