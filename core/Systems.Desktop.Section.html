    Systems.Desktop.Section behaviour (mica v0.1.0)

    Copy Markdown View Source

    A section on the Desktop page (/desktop), shown after Recent items, or before them when placement/0 says so.

    Systems contribute sections with Mica.System.desktop_sections/0; the page shows the sections of each placement in Mica.SaaS.systems/0 order.

    defmodule Systems.Notes.DesktopSection do
  use Systems.Desktop.Section
  use Gettext, backend: MicaWeb.Gettext

  alias Systems.Notes

  @impl true
  def id, do: :notes

  @impl true
  def title, do: dgettext("eyra-notes", "desktop.title")

  @impl true
  def view_model(user, _assigns) do
    case Notes.Public.list_unread(user) do
      [] -> nil
      notes -> %{notes: notes}
    end
  end

  @impl true
  def render(assigns) do
    ~H"""
    <Notes.View.list notes={@vm.notes} />
    """
  end
end

    Sections are display-only: they render inside Systems.Desktop.View, which handles none of their events, so a phx-click in a section crashes the view. Links to other pages work.

    A preview can expose a full-list link with full_list/1. To reuse the generic full-list page, route Systems.Desktop.FullListPage with this section's id as its LiveView action and implement full_view_model/2. The same render/1 renders that content, including its empty state. Returning nil makes the full page unavailable. Updates can target the generic page with the current user, just like Desktop updates.

    The page builds the section's view model with the page's, so a section refreshes when the page does. To refresh it live, the section's system has its own Switch that intercepts the signals of its data and calls update_routed(Systems.Desktop.Page, user, from_pid) for the affected user.
